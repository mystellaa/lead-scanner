# Lead Scanner

一个基于 Python、Tkinter 和 OCR 的本地截图线索整理工具。

它把截图识别、字段提取、名单匹配、批次管理和 CSV 导出串成一个桌面工作流，适合需要从图片中整理结构化记录的场景。

## 功能

- 从剪贴板粘贴截图，或选择单张图片、图片文件夹
- 支持 JPG、JPEG、PNG
- 使用中文 OCR 识别图片文字
- 从识别结果中提取联系人标识和手机号
- 支持群聊/评论布局与关注列表布局
- 使用本地名单提高联系人匹配准确率
- 支持单平台批量导入和代登记两种批次模式
- 当前批次独立保存，可复制指定列到外部表格
- 支持导入通讯录文本或 CSV，并勾选人员角色
- 支持业务分配：固定顺序或随机分配，可停用暂不参与分配的人员
- 保存 CSV、JSON 和本地配置，程序重启后可以继续使用

## 运行环境

- Windows
- Python 3.10 或更高版本
- Tkinter
- PaddleOCR
- OpenCV

## 安装

```powershell
python -m venv .venv
.venv\\Scripts\\activate
pip install -r requirements.txt
```

首次运行时，OCR 引擎可能需要下载模型文件。模型缓存由本地运行环境管理。

## 启动

```powershell
python main.py
```

也可以在 Windows 中运行 `启动程序.bat`。

## 基本流程

1. 选择输入模式。
2. 粘贴截图，或选择图片文件。
3. 选择识别布局。
4. 点击开始识别。
5. 在结果表格中检查字段。
6. 按需分配业务人员或复制当前批次。
7. 导出 CSV。

## 两种输入模式

### 单平台批量导入

用于同一批图片属于同一来源的情况。开始识别前需要选择来源，批次中的记录会自动继承该来源。

### 代登记

用于来源暂时不明确，或代其他人员登记的情况。此模式允许先识别，来源字段可以留空，后续再补充。

两种模式相互独立。下一批不会因为上一批的来源或名单而被强制限制。

## 名单与角色

名单保存在 `data/roster.json`。可以在名单管理窗口中导入 `.txt` 或 `.csv` 文件，使用分号、中文分号或换行分隔记录，然后为每条记录勾选角色：

- 运营
- 业务

导入后的角色会用于联系人匹配和业务分配。原始通讯录内容只保存在本地数据目录，不应提交到公开代码仓库。

## 业务分配

业务分配窗口支持：

- 固定顺序轮转
- 随机分配
- 勾选或取消参与分配的人员
- 为新人配置带教关系

分配结果会写入当前线索记录。导出或复制时使用完整的本地账号标签，避免只输出简称造成匹配错误。

## 剪贴板导出

“复制当前批次”只处理本次识别产生的记录，不会混入历史记录。复制窗口可以选择列，并支持是否复制表头。

为了适配不同表格，导出内容使用制表符分隔，字段中的换行和制表符会被清理，避免一条记录被拆成多行或多列。

## 数据文件说明

- `leads.csv`：线索记录
- `roster.json`：当前角色名单与本地账号映射
- `contact_roster.json`：最近一次通讯录导入结果
- `assignment_prefs.json`：业务分配方式和启用状态
- `data/paste/`：剪贴板截图缓存

数据文件默认保存在项目目录下的 `data/` 中。请根据实际隐私要求决定是否备份或共享这些文件。

## 设计原则

- Tkinter 主线程只负责界面和定时刷新。
- OCR、文件读取和字段提取在后台线程执行。
- 后台线程不直接访问 Tkinter 控件。
- 提取规则放在无界面的纯函数中，便于测试和调整。
- 本地名单优先于模糊猜测，无法确定时保留待复核状态。
- 写入重要配置前保留原文件，异常时尽量维持已有数据可用。

## 隐私提示

本项目默认处理本地截图、联系人标识和手机号等敏感数据。请不要把截图、名单、导出的 CSV 或 `data/` 目录提交到公开仓库。建议使用 `.gitignore` 忽略本地数据文件。
