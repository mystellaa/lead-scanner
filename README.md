# 视频号线索采集助手 · Lead Scanner V0.4.0

> 解决一句话：**多个视频号场景下，快速从截图里提取客户线索，并记住线索来自哪个视频号。**

> 🚀 **只想启动程序？双击本文件夹里的 `启动程序.bat`。**（其他 .py 文件不用管，详见文末「文件速查表」）

不做自动登录、不操作微信、不爬视频号。只做一件事：**截图 → OCR → 提取 → 结构化落表**。

---

## 一、它做什么

```
粘贴截图(Ctrl+V) → OCR 识别 → 认出「发布人」= 运营 → 抽取 手机号 / 内容 / 被@的业务
                                     ↓                            ↓
                        他负责哪几个平台 → 你选一个作为来源    去重后写入 leads.csv
```

核心是一条业务规矩：**截图里的发布人一定是运营**。所以

* **发布人 = 线索人**：读出「彭曦（AAa琉璃瓦老彭）」就知道这条线索是彭曦给的
* **手机号和发布人按行绑定**：一张图里好几位运营各自发言，号码不会串到别人名下
* **被 @ 的人 = 任务负责人（业务）**：`@韦东雅（…）` → 商务分给韦东雅
* **平台可以后补**：截图常常读不出「平台」，但读得出「发布人」——
  双击「来源平台」就只列**他负责的那几个账号**（彭曦 → 视频号-彭曦 / 本地推）
* **挡住噪音**：不在运营名单的名字（客户名、业务名）不会被当成线索人，只在备注里说明

其余特性：

* **粘贴即用**：截图工具截完直接 `Ctrl+V`，不用先存文件再挑选
* **快捷键**：`Enter` = 开始识别，`T` = 清空面板（焦点在输入框/列表里时不触发，不误吃按键）
* **临时模式 = 分批视图**：列表只显示本批新增的，方便一次性复制走；
  **数据始终写入总库**（这个开关只管列表显示，不管落库）
* **一键复制到剪贴板**：制表符分隔，粘进多维表格自动分列；默认不带表头，列可自选
* **内置名单校验**：线索人 / 任务负责人自动按公司名单纠正 OCR 错字（例：壹曦 → 彭曦）
* 手机号归一化：`138 1234 5678` / `138-1234-5678` / 全角 `１３８…` → 统一存 `13812345678`
* 不完整号码也保留，备注自动写「号码可能不完整」
* 自动去重：手机号重复的记录不会重复入库
* **导出可自选列**：勾哪些列就导哪些列，还能选择要不要表头
* 信息提取不到就留空，**绝不用错误数据填充**

**前置：Python 3.10 ~ 3.12**（python.org 官方安装包，安装时勾选 *Add Python to PATH*）。

```bash
cd lead_scanner
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-rapid.txt
```

**务必用虚拟环境，不要直接装进系统 Python** —— 原因见下面的「环境避坑」。

### 方案②（本机采用）：RapidOCR，轻量

```bash
.venv\Scripts\python.exe -m pip install -r requirements-rapid.txt
```

不需要 paddlepaddle，纯 pip 安装，模型内置，离线可用。

### 方案①（需求文档指定）：PaddleOCR

```bash
.venv\Scripts\python.exe -m pip install -r requirements-paddle.txt
```

> ⚠️ `paddlepaddle` 官方轮子支持到 **Python 3.12**。用 3.13 会报
> `Could not find a version that satisfies the requirement paddlepaddle`，
> 那就只能用方案②。

两个都装也没关系：**程序优先用 PaddleOCR，其次是 RapidOCR**。

---

### ⚠️ 环境避坑：不要把 Python 装在「绿色软件目录」里

部署时实际踩到的坑，值得记一笔：

本机的 `D:\软件\python.exe` 这个解释器，**只要 `import onnxruntime` 就直接段错误崩溃**。
排查结论：该目录里混进了 100 多个 `api-ms-win-crt-*.dll`（绿色版软件打包残留的转发层）。
Windows 加载 DLL 时会**优先搜索 exe 所在目录**，这些转发层把 VC++ 运行库劫持了，
进而把 onnxruntime 搞崩。

**症状识别**：界面能正常打开，但一点「开始识别」整个程序瞬间消失（无报错、无日志）。

**判断方法**：看你的 Python 目录里有没有一堆 `api-ms-win-*.dll`。
标准安装的 Python 目录只有 4 个 DLL（python3.dll、python312.dll、vcruntime140*.dll）。

**解决**：换用干净目录的 Python（如 `C:\Users\<你>\python312\`），或者一律用虚拟环境。
本项目就是这么解决的 —— `.venv` 基于干净的 `python312` 创建。

## 五、使用流程

| 步骤 | 操作 |
| --- | --- |
| ① | 顶部**输入或下拉**选来源视频号（可直接打字筛选）；想固定就点「设为默认」 |
| ② | **直接按 `Ctrl+V` 粘贴截图**（也可以用「粘贴截图」按钮 / 「选择图片文件」/「选择文件夹」批量导入） |
| ③ | 点「▶ 开始识别」，进度条走完即完成；识别在后台线程，界面不会卡死 |
| ④ | 结果表格查看线索；点「导出 CSV…」自选列导出；**双击单元格可直接改** |
| ⑤ | 要一批一批处理 → 勾上「**临时模式**」，列表只留本批，配合「复制本批」「清空面板」（见下节） |
| ⑥ | 底部还有「**名单管理**」（查看/导出运营、账号、业务名单）和「**更新日志**」（看版本变更） |

界面上会实时显示：**识别到：手机号 N 个 · 客户 M 位 | 本次新增 X 条，库内共 Y 条**
（临时模式下末尾变成「本批 N 条（已写入总库）」）。

### 快捷键

| 按键 | 作用 |
| --- | --- |
| `Ctrl+V` | 粘贴截图 |
| `Enter` | 开始识别（相当于点「▶ 开始识别」） |
| `T` | 清空面板：清掉待识别图片 + 列表显示（**不删总库数据**） |

> 这些快捷键**只在焦点不在输入框/列表上时生效** —— 你正在改单元格、输来源名、
> 或在图片列表里按 `T` 跳转时，不会被误触发。

### 粘贴怎么用

1. 用截图工具截图（Win11 按 `Win+Shift+S`，微信/QQ 自带截图也行）
2. 回到本程序窗口，按 `Ctrl+V`
3. 截图会存到 `data/paste/paste_时间戳.png` 并出现在下方列表里，自动选中预览
4. 可以连续粘多张，然后一次性点「开始识别」

> 在资源管理器里**复制了图片文件**再按 `Ctrl+V` 也可以，会把那些图片加进列表。
> 剪贴板里如果是文字（没有图），状态栏会提示「剪贴板里没有图片」。

### 总库模式 vs 临时模式（「临时」= 分批看图，不影响入库）

**两种模式都会把线索写进总库** `data/leads.csv`。区别只有一个：**表格里显示什么**。

| | 总库模式（默认） | 临时模式 |
| --- | --- | --- |
| 表格显示 | 全部历史线索 | **只有本批新增的** |
| 写入总库 | ✅ | ✅ **照样写** |
| 适合 | 查看全部、逐条核对 | 一批一批处理，**看完就复制走** |

「临时模式」的用法就是一条流水线：

```
贴截图 → 开始识别 → 列表里只有这一批（历史数据不掺进来）
                     ├── 「复制本批」→ 进剪贴板 → 粘到多维表格
                     └── 「清空本批」→ 只清空列表，开始贴下一批
```

* 「清空本批」**不会删数据** —— 线索早就写进总库了，它只是把列表擦干净
* 复制的是**制表符分隔**的文本，粘进飞书多维表格 / Excel / WPS 会自动分列
* 表格里**选中几行就只复制这几行**，没选中就复制本批全部
* 需要删数据请用「删除选中行」，那个是真的删（会二次确认）

### 关于「来源」的初始状态

程序**故意不预选来源** —— 选错来源会让整批线索挂到别的账号上，而且事后很难发现。
所以每次启动输入框是空的，逼你确认一次。没选就点「开始识别」会拦下来提醒你。

如果习惯每天主要盯一个账号：选中它 → 点「**设为默认**」→ 下次启动自动选中。
想取消默认，把输入框清空再点一次「设为默认」。

来源多了以后不用翻列表，**直接在输入框里打字**就能筛（比如输「北海」就只剩北海相关的）。

### 选错来源了 / 数据要改怎么办

| 情况 | 怎么做 |
| --- | --- |
| **导入时来源选错了** | 顶部选好正确来源 → 表格里选中那几行（按住 `Ctrl` 多选）→ 点「**改为当前来源**」 |
| **某个字段识别错了** | **双击那个单元格**直接改。改完立刻写入 leads.csv |
| **线索人是空的** | 点「**补全线索人**」—— 按「来源平台 → 运营」的对应关系批量补上 |
| **这条根本不是线索** | 选中该行 → 点「**删除选中行**」（会先弹确认框） |

### 线索人是怎么定出来的？

两个来源，优先级从高到低：

**① 截图里的发布人（首选）**

```
彭曦（AAa琉璃瓦老彭）：        ← 发布人 = 彭曦
青海西宁别墅130方左右刘总 18697110000
@韦东雅（A真赞瓦业-韦东雅-13392262816）
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| 线索人 | 彭曦 | 发布人。**必须在运营名单里**，否则不算 |
| 联系方式 | 18697110000 | **和发布人按行绑定**（同一段里的人和号才算一对） |
| 任务负责人 | 韦东雅 | 被 @ 的人（@ 常写在正文下一行，程序会往后多看两行） |
| 内容 | 青海西宁别墅130方左右刘总 | 正文去掉号码 |

一张图里如果有好几位运营各自发言，**每个人只认自己那段里的号码**，不会串。

发布人的写法很随意，程序都能认：

* `彭曦（AAa琉璃瓦老彭）：` —— 带备注、带冒号
* `彭曦（AAa琉璃瓦老彭）` —— 带备注
* `彭曦` —— **光秃秃的昵称**（群里最常见，也最容易漏）
* `2 彭曦` —— OCR 把头像旁的楼层序号混进来了
* `彭曦（…）正文内容` —— 昵称和正文被 OCR 连成一行

关键是**行首是运营名**就认；`@` 开头是「提到别人」，不算发布人。

**② 来源平台反查（兜底）**

截图里认不出发布人时（比如只有一句「需要屋面瓦 138xxxx」），
就用你选的来源平台反查运营：

| 来源平台 | 自动填的线索人 |
| --- | --- |
| 视频号-北海服务商 | 王烔彤 |
| 本地推 | 彭曦 |
| 抖音-见真-梁毅 | 梁毅（没登记过，按名字推断） |

来源输入框右边会实时显示「**运营：xxx**」，选之前就能看到这条会归谁。

**两条兜底规则**

* 截图里出现但不在运营名单的名字（客户名、业务名）**不会被当成线索人**，
  只在备注里留一句「「阿May」不在运营名单」——既挡噪音，也留痕
* **发布人和所选来源平台对不上时会提醒**（比如彭曦发布的线索却选了视频号-梁毅），
  备注写「来源平台「X」属于 Y，与线索人 Z 不一致，请核对」，避免线索挂错账号

对**已经存在的旧数据**，点「补全线索人」按平台规则补（只补空着的，不动已有值）。
想关掉自动填充：`config.py` 里 `AUTO_FILL_PERSON_BY_PLATFORM = False`。

### 平台怎么选：双击就只列他自己负责的

选平台不用在十几个来源里翻 —— **双击「来源平台」单元格**，候选直接收窄成
**这行线索人负责的账号**（彭曦 → 视频号-彭曦 / 本地推）。

一批识别完之后，如果发布人都是同一位运营，**顶部的来源下拉也会自动收窄**到他的平台，
状态栏会提示一句。核对完直接点「开始识别」就行。

**双击不同字段，给的编辑器不一样**（能选的就不让你手打）：

| 字段 | 双击后出现 |
| --- | --- |
| 来源平台 | **下拉选择**（点箭头选，也可以手输） |
| 线索人 | **下拉选择**（运营名单） |
| 任务负责人 | **弹出勾选窗口** —— 按老业务 / 新人 / 带教分组，可多选；勾了新人会自动带上带教 |
| 图片来源 | 下拉选择（当前已添加的图片名） |
| 其他字段 | 普通文本输入框 |

回车 = 保存，`Esc` = 取消，点到别处也会保存。

表格上还有**右键菜单**：修改此单元格 / 改为当前来源 / 打开原图 / 删除选中行。

> ⚠️ 修改和删除都是**立即写盘、不能撤销**的。改动之前想留底稿，先点「导出 CSV…」备份一份。

## 六、输出数据

主库固定为 `lead_scanner/data/leads.csv`（UTF-8 带 BOM，Excel 双击不乱码）。
**列的顺序和名称按「导入飞书多维表格」对齐**：

| 联系方式 | 来源平台 | 线索人 | 任务负责人 | 内容 | 客户ID | 备注 | 发现时间 | 图片来源 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 18697110000 | 视频号-北海服务商 | 彭曦 | 韦东雅 | 青海西宁别墅130方左右刘总 |  |  | 2026-10-04 15:30 | image001.png |
| 13812345678 | 视频号-北海服务商 |  |  | 需要屋面瓦 | 赵明刚 |  | 2026-10-04 15:30 | image002.png |
| 138123456 | 视频号-佛山服务商 |  |  |  | 韦师傅 | 号码可能不完整 | 2026-10-04 15:31 | image003.png |

* **内容**：消息正文，自动去掉号码和「联系/电话/微信」这类尾巴
* **线索人**：发消息的人（`彭曦（AAa琉璃瓦老彭）：` → `彭曦`）
* **业务**：被 @ 的人（`@韦东雅（…-13392262816）` → `韦东雅`）
* **备注**：系统提示，比如「号码可能不完整」
* **图片来源**：截图文件名。想连同原图归档的话，原图在 `data/paste/`（粘贴的）或你选的原路径
* 提取不到的字段一律**留空**，不会瞎猜填充

### 导出 CSV

点「导出 CSV…」会先弹一个选项框：

* 勾选要导出的列（默认全选，可以只留「联系方式 / 来源平台 / 线索人 / 任务负责人」这种精简组合）
* 是否包含表头（不勾的话第一行就是数据，方便直接喂给别的系统）
* **保存为默认导出选项** —— 勾上之后，下次打开这个对话框会自动带出这次的勾选，不用每次重新点
* 「导出 CSV」是**另存一份**，不会动主库
* 导出的是**表里当前显示的那些**：总库模式 = 全部，临时模式 = 本批

> 默认文件名带时间戳（`线索导出_20261004_1630.csv`），而且**不允许保存到主库路径** ——
> 主库是原始数据，被覆盖后找不回来。

### 复制到剪贴板

不想落文件、只想直接粘到多维表格，就用「**复制本批**」：

* 输出**制表符分隔**的纯文本，粘进飞书多维表格 / Excel / WPS 自动分列
* **默认不带表头**（粘过去表头会变成一行数据）
* 选中几行就复制这几行，没选中就复制表里当前全部
* 「**复制设置**」可以勾选要哪些列、要不要表头 —— 和导出的选择方式一样，
  点确定即存为默认，之后「复制本批」直接按这个输出

> 设置存在 `data/copy_prefs.json`；导出的设置存在 `data/export_prefs.json`，两者互不干扰。

### 手机号识别规则

| 截图里的写法 | 识别结果 | 备注 |
| --- | --- | --- |
| `13812345678` | 13812345678 | |
| `138 1234 5678` | 13812345678 | |
| `138-1234-5678` | 13812345678 | |
| `138.1234.5678` | 13812345678 | |
| `１３８１２３４５６７８`（全角） | 13812345678 | |
| `138123456`（9位） | 138123456 | 号码可能不完整 |
| `12345678901` | 不提取 | 前缀不是有效的手机号段 |
| `18812345678901`（14位） | 不提取 | 超长数字串，避免误报 |

少于 7 位的数字直接丢弃（截断噪声太大，误报率高）。

### 线索人 / 业务 / 内容 识别规则

群聊截图（公司线索群）里的三要素：

| 字段 | 怎么认 | 例子 |
| --- | --- | --- |
| 线索人 | 「昵称（备注）」格式的发送者行，**优先采纳带冒号的**（引用块里的发送者标记最可信） | `彭曦（AAa琉璃瓦老彭）：` → `彭曦` |
| 业务 | `@` 后面的人名 | `@韦东雅（A真赞瓦业-…）` → `韦东雅` |
| 内容 | 带号码那行去掉号码后的正文，并清掉尾部「联系 / 电话 / 微信」等词 | `18697110000青海西宁别墅130方左右刘总` → `青海西宁别墅130方左右刘总` |

> ⚠️ **`@某某（…）` 括号里的号码不算客户线索**。那是被 @ 的人（业务员）自己的电话，
> 比如 `@韦东雅（A真赞瓦业-韦东雅-13392262816）` 里的 `13392262816` 会被主动排除，
> 不会混进线索列表。

### 客户ID 识别规则（按优先级）

1. `用户：赵明刚` / `昵称: 阿May` —— 标签和值在同一行
2. `用户：` 换行后 `赵明刚` —— 标签独占一行（**视频号评论区截图最常见的形式**）
3. `@小张` —— @昵称
4. 兜底启发式：找最像昵称的那一行
5. 都不匹配就留空 —— 留空比填错好

> 群聊截图通常没有「用户：」这种标签，客户ID 大概率是空的 —— 这是正常的，
> 客户信息在「内容」字段里（比如「…刘总」）。

识别不出来时不会瞎猜，宁可为空，避免污染数据。

### 去重规则

默认（`config.DEDUP_STRICT_BY_ID = False`）：

* 手机号重复 → 跳过，不重复保存
* 没有手机号时，`客户ID + 来源平台` 重复 → 跳过
* **同一个客户ID留了不同号码 → 保留**，备注标「同一客户ID已有其它号码」

> 需求文档写的是「手机号相同 **或** 客户ID相同」即判重。但直接照字面实现会有个坑：
> 同一张截图里同一个客户留了两个号码，第二条会被第一条以「客户ID重复」挤掉。
> 所以默认走上面这套更贴合实际业务的口径。
> 如果你要严格按文档执行，把 `config.py` 里的 `DEDUP_STRICT_BY_ID` 改成 `True` 即可。

## 九、常见问题

**Q：临时模式下我识别完就关程序了，数据还在吗？**
A：在。线索**一律写入总库**，临时模式只影响「列表显示什么」，不影响落库。
   关程序不会丢数据，下次启动列表会重新显示全部线索。

**Q：为什么截图里是「阿May」发的，线索人却是别人（或为空）？**
A：因为规矩是「发布人一定是运营」。「阿May」不在运营名单里，所以不被当作线索人，
   这时会退回用来源平台反查运营，并在备注里写一句「「阿May」不在运营名单」。
   如果她确实该算，把她加进 `roster.py` 的运营名单即可。

**Q：我选了平台，为什么线索人是空的？**
A：说明这个平台在名单里没登记对应运营。看来源输入框右边的提示：
   显示「运营：未登记」就是这个问题 —— 去 `roster.py`（或 `data/roster.json`）把这个账号
   挂到某位运营名下即可。也可以在「名单管理」窗口里核对账号清单。

**Q：批量识别到一半，我发现来源选错了怎么办？**
A：不用重跑。顶部选对来源 → 表格里选中那几行 → 点「改为当前来源」，一秒改完。

**Q：点开始识别提示「未检测到可用的 OCR 引擎」**
A：说明没装引擎。执行 `pip install rapidocr-onnxruntime`，或 `pip install paddlepaddle paddleocr`。

**Q：第一次识别特别慢**
A：PaddleOCR 在下载模型。加载完成后会写进日志「OCR 引擎已就绪」。也可以提前手动跑一次预热。

**Q：pip 安装很慢 / 超时**
A：换国内源：`pip install -r requirements-rapid.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

**Q：界面能开，但导出提示文件被占用**
A：`leads.csv` 正被 Excel 打开。关掉 Excel 再导出（或直接导出到别的文件名）。

**Q：识别结果里客户ID张冠李戴**
A：截图里没有 `用户：` / `昵称：` 这类标签时，只能靠启发式猜。建议截图时**把昵称那一行也截进去**，
识别准确率会高很多。也可以在结果表里手工改——不过那是 V0.2 的编辑功能，目前建议直接编辑 `leads.csv`。

**Q：界面字体很难看 / 中文是方块**
A：程序会自动挑微软雅黑。若系统没有，编辑 `config.py` 的 `UI_FONT_CANDIDATES` 加上你机器上的中文字体。

**Q：程序里的「重命名来源」之后，历史数据还是旧名字？**
A：历史记录不会被批量改写（避免误伤）。要统一就手工编辑 `leads.csv` 的「来源平台」列。

**Q：按 Ctrl+V 没反应？**
A：① 先确认剪贴板里真的有图（用截图工具截完才算，光复制文字不行）；
② 保证焦点在本程序窗口上再按；③ 状态栏会告诉你原因，比如「剪贴板里没有图片」。

**Q：表格和 CSV 里怎么多了几列？之前的文件还能用吗？**
A：新增了「内容 / 线索人 / 业务」三列。程序启动时会自动检测旧版 `leads.csv`，
先备份到 `data/backup/`，再按新表头重写 —— **老数据不会丢**，只是新列为空。

**Q：导出时能不能只导手机号和来源平台？**
A：可以。点「导出 CSV…」→ 点「全不选」→ 勾上「手机号」「来源平台」，
不需要表头就把「包含表头」也取消，导出的文件就只有这两列。

**Q：一张图里有好几个客户，会串行吗？**
A：不会。程序会**逐行就近绑定**：哪个号码挨着哪个昵称，就归到那个人名下。

**Q：窗口能调小吗？我要两个程序并排双开。**
A：默认就是 **980×660** —— 1920 宽的屏幕两个并排刚好放下，不用最大化。还能再拖到最小 850×560。
   想改默认尺寸，改 `config.py` 里的 `WINDOW_SIZE` 即可。

## 十一、调参速查（都在 `config.py`）

| 参数 | 作用 |
| --- | --- |
| `DEDUP_STRICT_BY_ID` | `True` = 严格按需求文档（客户ID相同即判重）；`False` = 同客户多号码保留 |
| `OCR_ENGINE_PREFERENCE` | 引擎优先级，可改成 `["rapidocr"]` 强制用轻量引擎 |
| `OCR_PREPROCESS` / `OCR_UPSCALE` | 是否启用 OpenCV 灰度+放大预处理，以及放大倍数（小截图识别更准） |
| `OCR_MIN_SCORE` | 丢弃低于该置信度的文本行（默认 0.35，调高更严格） |
| `DEFAULT_SOURCES` | 首次启动时的默认视频号列表（之后以 `data/sources.json` 为准） |
| `ID_LABELS` | 客户ID 的标签词，遇到新写法可以往这里加 |
| `EXPORT_DEFAULT_FIELDS` | 导出对话框里默认勾选哪些列（点「保存为默认」后会记到 `data/export_prefs.json`） |
| `WINDOW_SIZE` | 启动时的窗口大小（默认 980×660，按双开设计的） |
| `CSV_FIELDS` / `CSV_HEADERS` | 数据字段与表头文字（改这里会触发自动表头迁移） |
| `ROSTER_AUTO_CORRECT` | `True` = 名字与名单只差一字时自动改正；`False` = 只提示不改数据 |
| `CHECK_NAMES_AGAINST_ROSTER` | 是否对「不在名单里」的名字做备注提示 |
| `TEMP_MODE_DEFAULT` | 启动时是否默认进临时模式（默认 `False` = 列表显示全部） |
| `AUTO_FILL_PERSON_BY_PLATFORM` | 线索人为空时，是否用「来源平台 → 运营」自动补上（默认 `True`） |
| `COPY_HEADER_DEFAULT` | 复制到剪贴板是否带表头（默认 `False`）；列的选择存 `data/copy_prefs.json` |
| `CHANGELOG` | 程序内「更新日志」窗口显示的内容（新增版本往最前面加） |

## 十三、名单管理（运营 / 账号 / 业务）

程序内置三份名单，点底部「**名单管理**」按钮查看，也可以在窗口里一键导出。

| 名单 | 内容 | 用在哪 |
| --- | --- | --- |
| 账号 | 6 位运营各自负责的账号，共 13 个 | 「来源视频号」下拉自动补齐这些账号 |
| 运营 | 彭曦、刘一手、梁毅、王可、叶虹池、王烔彤 | 校验截图里的「线索人」是不是自己人 |
| 业务 | **老业务 7 人 / 新人 7 人 / 带教 1 人（胡丹）** | 校验「任务负责人」，并自动带教 |

### 任务负责人：可能是两个人（新人 + 带教）

分给新人的线索，**任务负责人是两个人**：新人本人 + 带教胡丹。程序会自动处理：

* 认出名单里的人名 → 自动补上带教 → `罗淑冰,胡丹`
* **胡丹永远排在最后**，一眼能分清谁是新人
* 分给老业务的线索**不会**被塞胡丹（`韦东雅` 就还是 `韦东雅`）
* 多人之间用**英文逗号**分隔 —— 这是多维表格识别「多人」字段的格式

实测你给的那串数据：

| | 结果 |
| --- | --- |
| 原文 | `13985305396 → 抖音-见真-梁毅 → 梁毅(A真赞瓦业-梁毅) → 真赞瓦业-罗淑冰18689239098,A佛山真赞瓦业-胡丹(A真赞瓦业-胡丹18665418517)` |
| 联系方式 | `13985305396` |
| 线索人 | `梁毅` |
| 任务负责人 | **`罗淑冰,胡丹`** |

> 那串里还有两个号码（`18689239098` 是罗淑冰的、`18665418517` 是胡丹的），
> 程序会**自动排除**：**名单里的人名后面紧跟的号码**视为该联系人自己的电话，不是客户线索。
> 所以不会因为业务员写了签名档就多出一堆假线索。

### 名字自动纠错

OCR 经常认错人名（实测：**彭曦** 被认成 **壹曦**）。程序会拿识别结果跟名单比对：

* 和名单里某个人**只差一个字** → 自动改成名单里的写法，备注记下
  「已按名单校正：壹曦 → 彭曦」，可追溯、可复查
* 名单里完全找不到 → 备注提示「线索人「XXX」不在运营名单」，方便发现漏登或识别错误

不想要自动改数据？把 `config.py` 里的 `ROSTER_AUTO_CORRECT` 改成 `False`，
就只提示、不改值。

### 导出名单（专门给多维表格用）

「名单管理」窗口底部两个按钮：

* **导出「运营-账号」表** → `运营,账号` 两列，**一行一个账号**
* **导出「业务名单」表** → `分组,业务` 两列，**一行一个人**（老业务 / 新人 / 带教 分列）

**为什么必须拆成一行一条**：一个人对应多个账号时，挤在一个格子里写成
`王烔彤（视频号-北海服务商，视频号-来宾服务商…）`，导入多维表格只会得到一坨文本。
拆成多行，多维表格才能识别成**同一个人的多条关联记录**，可以直接按人分组、按账号统计。

### 怎么加人 / 改账号

**方式一**：改 `roster.py` 里的 `DEFAULT_OPERATORS` / `DEFAULT_SALES`（改完重启程序）

**方式二（推荐，不用改代码）**：在 `data/` 下新建 `roster.json`：

```json
{
  "operators": [
    {"name": "彭曦", "accounts": ["视频号-彭曦", "本地推"]},
    {"name": "新同事", "accounts": ["视频号-新账号"]}
  ],
  "sales": [
    {"group": "老业务", "members": ["张悦", "韦东雅"]},
    {"group": "新人", "members": ["胡丹", "朱倩琳"]}
  ]
}
```

这个文件只要存在，就会**整体覆盖**内置名单（所以要从完整的名单开始写）。
不确定格式就照着「名单管理」窗口里导出的对照表抄。

| 层 | 文件 | 职责 |

| 存储层 | `database.py` | CSV 读写、去重、表头迁移、按勾选列导出、备份 |
| 数据层 | `data/` | leads.csv、sources.json、roster.json、paste/、backup/、运行日志 |

### 模块依赖（无循环）

```
ui.py            → config, database, ocr, phone_extract, roster
ocr.py           → config
phone_extract.py → config（roster 是函数内延迟导入）
database.py      → config
roster.py        → config
config.py        → （不依赖任何内部模块）
main.py          → config
```

`config.py` 在最底层，所有模块都依赖它 —— 所以**改参数只需要动这一个文件**。
`config ↔ roster` 本来会循环，用「函数内延迟导入」化解掉了。

### 一次识别的线程模型

```
主线程（Tkinter）                              后台线程
──────────────────────                        ──────────────────
按 Ctrl+V → 图片存进 data/paste/
点「开始识别」 ───── 启动线程 ───────────────→  逐张图：OCR → 提取字段
每 80ms 查一次队列 ←──── 结果队列 ────────────  每张完成就丢一条结果进去
写 CSV + 刷新表格
```

**铁律**：后台线程只碰数据和文件、**绝不碰界面控件**；主线程只碰界面、不做重活。
跨线程操作 Tkinter 控件会随机崩溃 —— 这是 Tkinter 唯一正确的用法。

### 三处容错（都保证不中断主流程）

* **OCR 引擎**：PaddleOCR 装不上 → 自动换 RapidOCR → 两个都没有才弹窗告诉你怎么装
* **字段变了**：启动时比对表头，不一致就先备份到 `data/backup/` 再按新表头重写，老数据保留
* **名单出问题**：`roster` 读不到或报错时静默跳过校验，识别照常完成

### 为什么用 CSV 而不是数据库

因为你的下游是**多维表格**：CSV 能直接看、直接导入、直接用手改。
代价是数据量大时变慢 —— 当前量级（几千条）完全够用。
真到十万条以上，只需要替换 `database.py` 这一个文件，上层代码不用动。

# 复制与人员账号更新

复制到剪贴板固定不包含列名，旧复制设置中的表头选项也不再生效；CSV 导出仍可选择是否带表头。每次复制都会确认本次需要的列，未选列不会输出，单元格内的制表符和换行会转换为空格。

复制和导出时，线索人、任务负责人会使用运营和业务名单对应的完整账号名。
新人自动带上胡丹，多个负责人用英文逗号连接，并保留在同一单元格。例如：

```text
真赞瓦业-罗淑冰18689239098,A佛山真赞瓦业-胡丹(A真赞瓦业-胡丹18665418517)
```

总库和界面继续使用规范姓名。完整账号映射在 `roster.py` 的 `DEFAULT_ACCOUNT_IDS`，也可通过 `data/roster.json` 的 `account_ids` 对象覆盖；名单之外的同事没有新增到运营或业务分组。

登记方式分为“代他人登记”和“同平台批量导入”。默认代登记时平台留空，每张图按自身内容识别运营；同平台批量导入需要先选平台。完成一批不会按该运营收窄下一批的平台列表。代登记记录的平台可之后在表格中逐条补充。

运行 `create_desktop_shortcuts.ps1` 可在桌面创建 `Lead Scanner` 文件夹，包含启动程序、项目目录、数据目录和 GitHub 四个快捷入口。
